1. Le problème, en une phrase

On a 50 à 100 étudiants qui arrivent à la rentrée avec un choix de LV2 (Allemand / Espagnol / autre). On doit les répartir dans des groupes (LV2, LV1, TP, TD) de capacité limitée, en respectant le choix de chacun, en gardant les groupes équilibrés, et en décidant combien de groupes on ouvre réellement.

La question n'est pas « quel algorithme ? » mais « qu'est-ce qu'on décide en dur, et qu'est-ce qu'on optimise ensuite ? ». Le modèle répond :

  • Dur, d'abord : combien de groupes on ouvre (k(t)), qui va dans quel groupe compatible, capacité par capacité. C'est la structure.
  • Souple, ensuite : parmi toutes les affectations valides, celle qui équilibre le mieux les effectifs. C'est la qualité.

2. Données d'entrée

2.1 L'ensemble des étudiants s

Un dictionnaire {identifiant: choix LV2} :

s = {1: "Allemand", 2: "Espagnol", 3: "Allemand", ...}

Pourquoi un dict et pas une liste ? Parce qu'on doit identifier chaque étudiant dans la solution finale (aff[e] = "TP2"). La clé = l'identifiant stable.

2.2 Les groupes proposés groupes

Un dictionnaire {nom du groupe: capacité maximale} :

groupes = {"TP1": 16, "TP2": 16, "TD1": 36, "LV2_A": 24, ...}

La capacité C(g) est le maximum absolu : on ne peut pas dépasser, même si la place se libère.

2.3 Le nombre de groupes ouverts k

Paramètre dur (contrainte, pas objectif). S'il vaut None, tous les groupes proposés sont ouverts. Sinon, exactement k d'entre eux seront ouverts.

2.4 La compatibilité compat

Dictionnaire {identifiant: liste des groupes compatibles}. Un étudiant en Allemand ne peut aller que dans des groupes Allemand, etc.

compat = {1: ["TP1", "TP2"], 2: ["TP3"], ...}

3. Variables de décision

3.1 x[e, g] : binaire, « étudiant e dans le groupe g »

$$x_{e,g} = \begin{cases} 1 & \text{si l'étudiant } e \text{ est affecté au groupe } g \\ 0 & \text{sinon} \end{cases}$$

C'est la seule vraie variable de décision. Tout le reste (effectifs, indicateurs) en découle.

3.2 n[g] : effectif du groupe g

$$n(g) = \sum_{e \in s} x_{e,g}$$

Calculé (pas indépendant) : c'est la somme des affectations.

3.3 y[g] : binaire, « le groupe g est-il ouvert ? »

$$y_g = \begin{cases} 1 & \text{si le groupe } g \text{ est ouvert (au moins 1 étudiant)} \\ 0 & \text{sinon} \end{cases}$$

Pourquoi une variable dédiée ? Parce qu'on décide combien de groupes on ouvre avant d'équilibrer. Sans y, on ne pourrait pas imposer « exactement k groupes ».

3.4 e[g] : variable auxiliaire pour l'équilibre

$$e_g = |k \cdot n(g) - N|$$

On utilise une égalité absolue (AddAbsEquality) pour dire au solveur « e[g] vaut la valeur absolue de k·n(g) − N ». C'est comme ça qu'on linéarise la valeur absolue en CP-SAT (pas besoin de abs() manuel).

4. Contraintes dures C1 → C7

C1 — Un seul groupe par étudiant

$$\forall e \in s : \sum_{g \in G} x_{e,g} = 1$$

Chaque étudiant est exactement dans un groupe. Ni deux, ni zéro.

C2 — Capacité maximale

$$\forall g \in G : \sum_{e \in s} x_{e,g} \le C(g)$$

Le groupe ne dépasse jamais sa capacité physique.

C3 — Compatibilité (choix LV2)

$$\forall e \in s, \forall g \notin \text{compat}(e) : x_{e,g} = 0$$

Un étudiant Allemand ne peut pas être dans un groupe Espagnol. On force à 0 les variables interdites.

C4 — Hiérarchie TP ⊂ TD (formalisée, non codée ici)

$$\forall tp \in TP : \text{parent}(tp) \in TD \implies n(tp) \le n(\text{parent}(tp))$$
À dire au prof : cette contrainte est dans la formalisation mais pas dans le code CP-SAT actuel, car l'instance de test ne mélange pas les types. Elle sera ajoutée quand on affectera TP+TD+LV2+LV1 en une seule passe.

C5 — Exactement k groupes ouverts (dur, avant l'équilibre)

$$\sum_{g \in G} y_g = k$$

C'est le cœur du modèle « dur avant souple ». L'ancienne version mettait le nombre de groupes dans un objectif souple (f2) : le solveur pouvait ouvrir 40 TP de 2 étudiants si ça « coûtait moins cher ». Maintenant c'est une contrainte dure : on décide k en amont (c'est une décision d'organisation, pas un réglage d'optimisation).

C6 — Rien dans un groupe fermé (lien y / x)

$$\forall g \in G : n(g) \le C(g) \cdot y_g$$

Si y_g = 0 (fermé), alors n(g) ≤ 0, donc n(g) = 0. Un groupe fermé ne prend personne. C'est une big-M classique (ici M = C(g)).

C7 — Un groupe ouvert a au moins un étudiant

$$\forall g \in G : y_g \le n(g)$$

Symétrique de C6 : si y_g = 1 (ouvert), alors n(g) ≥ 1. Pas de groupe ouvert vide.

Résumé C5-C7 : on force exactement k groupes à être utiles. Ni plus (sinon groupe vide), ni moins (sinon on triche sur la capacité). C'est ça, « structurer d'abord, équilibrer ensuite ».

C8 (implicite) — Étudiant non affecté (optionnel)

Dans les instances avec cas particuliers (césure, redoublant), on peut retirer ces étudiants de s avant de lancer le modèle, ou ajouter une contrainte de couverture partielle. Ici, on les retire.

5. Objectif : f1 relative, forme entière, normalisation

5.1 L'ancienne f1 et ses défauts

L'ancienne version minimisait :

$$f_1 = \sum_{t} \sum_{g \in G(t)} \left| n(g) - \frac{N(t)}{k(t)} \right|$$

Défaut 1 : pas normalisée entre types. Un écart de 2 étudiants est anodin sur un TD de 36, énorme sur un TP de 5. La formule les pèse pareil → les gros groupes (TD) dominent.

Défaut 2 : L1 avec somme fixe. Comme ∑n(g) = N est imposé par C1, ∑(n(g) − N/k) = 0 toujours. L'absolu ne mesure que la moitié de l'histoire.

5.2 La nouvelle f1 : déviation relative

$$f_1 = \sum_{t} \sum_{g \in G(t)} \frac{\left| n(g) - \frac{N(t)}{k(t)} \right|}{\frac{N(t)}{k(t)}}$$

Pourquoi relative ? Parce qu'un étudiant de trop pèse 20% sur un TP de 5 mais 3% sur un TD de 36. On veut que chaque pourcentage de déséquilibre compte pareil, quel que soit la taille du groupe.

5.3 Forme entière équivalente (celle du code)

Multiplier par k(t) (positif) ne change pas le minimiseur :

$$f_1' = \sum_{t} \sum_{g \in G(t)} \left| k(t) \cdot n(g) - N(t) \right|$$

Pourquoi cette forme en code ? Parce que CP-SAT travaille en entiers. AddAbsEquality(v, k*n(g) - N) est exact, sans flottants, sans approximation. C'est le même minimiseur que la version relative.

5.4 Normalisation explicite (justification chiffrée)

On calcule les bornes de f1' :

  • Pire cas (f_max) : tous les étudiants dans un seul groupe (les autres fermés) : $f_{\max} = 2N(k-1)$
  • Meilleur cas (f_min) : répartition aussi proche que possible de l'idéal. Avec $r = N \bmod k$ (le reste de la division), $f_{\min} = 2r(k-r)$. Si r = 0, N est divisible par k → f_min = 0 (équilibre parfait).

La fonction objectif normalisée :

$$\tilde{f_1} = \frac{f_1' - f_{\min}}{f_{\max} - f_{\min}} \in [0, 1]$$

Exemple chiffré : N=12, k=3. f_max = 2*12*2 = 48, r=0, f_min=0. Si la solution donne 6/3/3 : f1' = |3*6-12|+|3*3-12|+|3*3-12| = 6+3+3 = 12, f1_norm = 12/48 = 0.25. Si solution 4/4/4 : f1' = 0, f1_norm = 0.

Deuxième exemple (non divisible) : N=10, k=3. r=1, f_min=2*1*2=4, f_max=2*10*2=40. Solution optimale 4/3/3 : f1' = |12-10|+|9-10|+|9-10| = 2+1+1 = 4 = f_min, donc f1_norm = 0. La normalisation met à 0 le meilleur atteignable, ce qui permet de comparer des instances de tailles différentes.

5.5 Pourquoi normaliser est indispensable (avouer au prof)

Sans normalisation, f1' peut valoir 48 (étudiants) quand un autre critère (ancien f2) vaut 5 (groupes). Dans une somme pondérée w1*f1 + w2*f2, le poids w2 est mort : f1 l'écrase. Une fois normalisées, les poids w deviennent des taux d'échange interprétables (« j'accepte 1 unité d'équilibre relatif pour 2 groupes fermés »). C'est ça, justifier.

5.6 f2 et f3 : où sont-elles passées ?

  • Ancien f2 (nombre de groupes ouverts) : absorbé par C5 (dur). On ne « minimise plus » le nombre de groupes, on le décide.
  • Ancien f3 (parallélisation / créneaux) : supprimée. Le nombre de salles R(t) n'était jamais justifié (d'où vient-il ?). La schedulabilité est portée par le choix de k(t) en entrée : si k(t) groupes tiennent dans H créneaux max, la solution est schedulable ; sinon, on a un mauvais k(t), pas un mauvais modèle.
  • f4 (robustesse / affectation tardive) : reportée semaine 6, pas dans ce code.

6. Indicateurs retournés par resoudre()

La fonction retourne 4 valeurs :

ValeurTypeContenu
statutintStatut du solveur (OPTIMAL, FEASIBLE, INFEASIBLE, …)
affdict{etudiant: groupe} — la solution (vide si infaisable)

Les 4 indicateurs

IndicateurDéfinitionInterprétation
kNombre de groupes réellement ouverts (∑y(g))Doit être égal au k demandé (C5)
f1∑|k·n(g) − N| (forme entière)Écart brut (non normalisé)
f1_norm(f1 − f_min)/(f_max − f_min)Écart relatif dans [0,1], comparable entre instances
maxminmax n(g) − min n(g) sur les groupes ouverts« Le plus gros groupe a x de plus que le plus petit » — plus lisible pour l'administration
Pourquoi maxmin en plus de f1 ? Parce que l'administration dit « équitable » au sens de « pas d'écart exagéré entre le plus gros et le plus petit ». C'est une mesure lisible, alors que f1 est une mesure agrégée. Les deux se complètent.

7. Le code, ligne par ligne

Voici le cœur du modèle (extrait de test_cpsat.py), avec le commentaire correspondant :

def resoudre(s, groupes, k=None, compat=None):
    m = cp_model.CpModel()
    k = len(groupes) if k is None else k  # k non spécifié -> tous les groupes ouverts

    # x[e,g] : étudiant e dans le groupe g
    x = {(e, g): m.NewBoolVar(f"x{e}_{g}") for e in s for g in groupes}

    # C1 : chaque étudiant dans exactement un groupe
    for e in s:
        m.Add(sum(x[e, g] for g in groupes) == 1)

    # C2 : capacité maximale
    for g, cap in groupes.items():
        m.Add(sum(x[e, g] for e in s) <= cap)

    # C3 : groupes compatibles avec le choix LV2 de e
    for e, a in (compat or {}).items():
        for g in set(groupes) - set(a):
            m.Add(x[e, g] == 0)

    # n[g] : effectif du groupe g (calculé)
    n = {g: sum(x[e, g] for e in s) for g in groupes}

    # y[g] : groupe g ouvert ou non
    y = {g: m.NewBoolVar(f"y{g}") for g in groupes}

    # C5 : exactement k groupes ouverts (dur)
    m.Add(sum(y.values()) == k)

    for g, cap in groupes.items():
        # C6 : rien dans un groupe fermé (big-M)
        m.Add(n[g] <= cap * y[g])
        # C7 : un groupe ouvert a au moins un étudiant
        m.Add(y[g] <= n[g])

    N = len(s)
    # e[g] : variable auxiliaire pour |k·n(g) − N|
    ecarts = [m.NewIntVar(0, k * N, f"e{g}") for g in groupes]
    for g, v in zip(groupes, ecarts):
        m.AddAbsEquality(v, k * n[g] - N)  # f1 : forme entière

    # Minimiser la somme des écarts
    m.Minimize(sum(ecarts))

    solver = cp_model.CpSolver()
    solver.parameters.max_time_in_seconds = 10
    statut = solver.Solve(m)

    if statut not in (cp_model.OPTIMAL, cp_model.FEASIBLE):
        return statut, {}, {}, {}  # infaisable -> dictionnaires vides

    # Reconstruire la solution
    aff = {e: next(g for g in groupes if solver.Value(x[e, g])) for e in s}
    eff = {g: solver.Value(n[g]) for g in groupes}
    ouverts = [g for g in groupes if solver.Value(y[g])]

    # Calculer les indicateurs
    f1 = sum(abs(k * eff[g] - N) for g in ouverts)
    r = N % k
    fmin, fmax = 2 * r * (k - r), 2 * N * (k - 1)
    norm = 0.0 if fmax == fmin else (f1 - fmin) / (fmax - fmin)
    ind = {
        "k": len(ouverts),
        "f1": f1,
        "f1_norm": round(norm, 3),
        "maxmin": max(eff[g] for g in ouverts) - min(eff[g] for g in ouverts),
    }
    return statut, aff, eff, ind

Chaque test vérifie une propriété du modèle. Voici la liste :

Test 1 — Équilibre (C1 + C2 + f1)

Test 4 — Choix LV2 (C3)

6 Allemand + 6 Espagnol, compat imposée. Vérifie que chaque étudiant est dans un groupe compatible avec son choix.

75 étudiants, 5 TP de 16. Vérifie que rien ne dépasse.

Test 6 — k imposé en dur (C5)

12 étudiants, 3 TP de 5, mais k=2. Capacité totale ouverte : 2*5=10 < 12 → INFEASIBLE. C'est la contrainte dure qui parle.

Test 7 — Indicateurs (f1, f1_norm, maxmin)

10 étudiants, 3 TP de 5. Solution optimale : 4/3/3. Calculs :

  • f1 = |3*4-10| + |3*3-10| + |3*3-10| = 2+1+1 = 4
  • r = 10%3 = 1, f_min = 2*1*2 = 4 → f1_norm = 0
  • maxmin = 4-3 = 1

Lecture

  • Au strict minimum, la capacité et la compatibilité bloquent : f1_norm monte jusqu'à 0.17 (17% de dégradation relative), maxmin jusqu'à 11 (le plus gros groupe a 11 de plus que le plus petit).
  • Un seul groupe de plus suffit à un équilibre parfait (f1=0, maxmin=0) sur les 10 instances.
  • f1 brut n'est pas comparable entre k (il contient le facteur k dans |k·n−N|). C'est tout l'intérêt de f1_norm, qui est dans [0,1] et comparable.
Conclusion pour le compte-rendu S3 : le modèle « dur avant souple » (C5-C7) fonctionne. On peut mesurer (indicateurs), comparer (normalisation), et justifier le compromis « un groupe de plus = équilibre parfait » (pertinence).

10. Le générateur d'instances (étendu)

Le fichier src/generateur_instances.py fournit :

  • generer_instance(n, seed, ...) : instance déterministe, bornes [50,100], distribution LV2 par défaut (45/20/35), choix tardifs, cas particuliers (césure, redoublant).
  • generer_n(mu=64, sigma=10) : effectif tiré selon une loi normale N(64, 10), tronqué au cadrage [50,100].
  • generer_lot(nb, seed) : lot de nb instances avec graines fixées (reproductible), distribution LV2 bruitée gaussiennement (σ=0.05) puis renormalisée.

Pourquoi une loi normale ? Parce que l'effectif réel d'une promo varie d'une année à l'autre autour d'une moyenne (ici 64). Une distribution uniforme ou fixe ne testerait pas le comportement du modèle sur des tailles réalistes.

12.4 Lecture

  • La référence manuelle est au niveau de la baseline : l'admin a rempli les TP à la volée (TP1 et TP2 pleins à 16, TP3 à 14 par manque d'étudiants). Ce n'est pas un jugement — c'est le comportement naturel d'un remplissage séquentiel.

  • Le gain est réel mais petit sur cette instance (car les capacités sont généreuses : 4×16=64 places pour 62 étudiants). Sur des instances plus serrées (voir banc d'essai section 9), le gain est bien plus visible.
  • Le temps de résolution (0.16s) est négligeable pour un usage pratique.

13.3 Démonstration par l'exemple

Sur l'instance réelle (section 12) :

  • La référence manuelle a f1_norm=0.011 (1.1% de dégradation) — presque parfait, car les capacités sont larges.
  • La baseline a le même score — preuve que le remplissage naïf est « assez bon » quand il y a de la marge.
  • CP-SAT atteint f1_norm=0 — l'équilibre parfait. Le gain est modeste ici, mais il devient critique quand les capacités sont serrées (section 9 : f1_norm=0.17 au strict minimum).
Réponse à la question « pertinence » : oui, l'objectif capture le vrai besoin. La f1 relative pénalise les déséquilibres proportionnellement à la taille du groupe (un étudiant de trop sur un TP de 5 = 20%, sur un TD de 36 = 3%). La normalisation permet de comparer des instances de tailles différentes. Et la contrainte dure C5 (exactement k groupes) garantit la stabilité de la planification, ce que l'ancien objectif souple f2 ne faisait pas.

15. Heuristique greedy constructif vs CP-SAT exact

15.1 Principe de l'heuristique

L'heuristique est un remplissage constructif (greedy) : on place les étudiants un par un, chacun dans le groupe compatible le moins chargé qui a encore de la place. L'astuce clé est l'ordre de passage :

  • Most constrained first : on traite d'abord les étudiants qui ont le moins de groupes compatibles. C'est une heuristique classique en satisfaction de contraintes : si on traite les plus contraints en dernier, on risque de les bloquer (plus aucun groupe compatible n'a de place).

15.2 Le code

def greedy(s, groupes, compat=None):
    aff = {}
    eff = {g: 0 for g in groupes}
    # most constrained first : les etudiants avec le moins de choix d'abord
    etuds = sorted(s.keys(), key=lambda e: len(compat[e]) if compat else len(groupes))
    for e in etuds:
        cand = [g for g in groupes if eff[g] < groupes[g]]
        if compat and e in compat:
            cand = [g for g in cand if g in compat[e]]
        if not cand:
            return {}, {}  # infaisable
        best = min(cand, key=lambda g: eff[g])  # groupe le moins charge
        aff[e] = best
        eff[best] += 1
    return aff, eff

15.5 Lecture

  • Qualité : le greedy atteint le même f1 que CP-SAT sur 10/10 instances. Sur ces instances (n ≤ 71, capacités larges), la stratégie « most constrained first + groupe le moins chargé » suffit à trouver l'optimum.
  • Temps : le greedy est 173 fois plus rapide (0.0002s vs 0.027s). Le gain serait encore plus net sur des grosses instances (n > 500), où CP-SAT peut devenir lent.
  • Garantie : CP-SAT garantit f1 = f_min (optimum prouvé). Le greedy ne garantit rien : sur des instances plus contraintes (capacités serrées, beaucoup de compatibilités), il peut être suboptimal. C'est là que le solveur exact fait la différence.
  • Usage pratique : greedy pour un premier résultat immédiat (ex. aperçu à l'écran pendant la saisie des choix) ; CP-SAT pour l'affectation officielle (qualité garantie, temps encore tout à fait acceptable à cette échelle).
Conclusion : l'heuristique greedy et le solveur CP-SAT sont complémentaires. Le greedy donne un résultat quasi-optimal instantanément ; CP-SAT garantit l'optimum en une fraction de seconde sur les instances du projet. Les deux convergent sur toutes nos instances testées, ce qui valide la cohérence du modèle.
